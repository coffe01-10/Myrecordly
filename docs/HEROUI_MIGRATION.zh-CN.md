# HeroUI UI 分支

本次迁移隔离在 `codex/heroui-ui` 分支上，基于 `codex/clip-controls` 的 `9693ad7`。它位于同级的 `recordly-heroui` Git worktree 中。原有的 `recordly` 检出及其未提交文件均保持原样。没有任何内容被合并或推送。

## 试用

从原检出目录：

```sh
cd ../recordly-heroui
npm run dev
```

全新的检出需要先执行 `npm install`，包括 Recordly 常规的原生辅助程序安装。依赖锁文件属于该分支。

要切回原状，请关闭开发应用，并在原来的 `recordly` 目录中运行 `npm run dev`。无需 reset、stash 或文件恢复。你可以在对比时同时保留两份检出。如果只想撤销 UI 打磨那一次改动，请使用 `git revert <refinement-commit>`。如果要在合并后撤销整个迁移，请按从新到旧的顺序 revert 该分支的提交，包括最初的 `93be193` 迁移。

## UI 方案

控件使用 HeroUI React 3.2.6 及其默认的浅色/深色主题，遵循[官方组件示例](https://heroui.com/en/docs/react/components)。这包括按钮、字段、开关、滑块、标签页、标签组、切换组、单选按钮、选择器、模态框、浮层、菜单、工具提示、取色器、进度指示器、骨架屏和 toast。React 19 和 Tailwind 4 满足 HeroUI v3 的要求。原有的 Radix、Sonner 和第三方取色器依赖已移除。

编辑器使用浮动检查器卡片、开放的画布和时间线、对齐的工具栏、一致的间距，以及克制的选中色。高级控件位于每个区块的开关之后；切换视图会保留项目取值。背景类型和其他互斥选项使用 TagGroup。头部跟随原生全屏状态，并在窄宽度下让项目标题居中。浮动层保持单一表面，而不是嵌套卡片和阴影。时间线块在两种主题下都保留 Recordly 原有的配色。检查器控件使用紧凑的 12–13px 文字和 32–36px 控件，区块标题为 14px。图片和视频壁纸网格共用同一个用于导入的加号磁贴，自定义磁贴上有小的移除控件，在悬停或键盘聚焦时显现。背景图库按标签顺序左右滑动。

片段轨道使用有界缓存和一个后台视频解码器采样真实源帧。采样遵循片段源偏移、速度以及可见时间线范围；它从不 seek 播放元素。缩放使用紧凑轨道，标签会根据块宽度自适应。标尺根据可用宽度选择刻度密度，红色播放头有一条白色中心线。摄像头圆角默认 100%；已保存的取值保持不变。新录制会继承已保存的摄像头外观，且 100% 是最大的超椭圆（squircle）半径，而不是圆形遮罩。三条紧凑的时间线轨道可在纵向滚动前容纳。浮层支持点击外部和 Escape 关闭，并共用同一个内边距层。导出状态保留充裕的内容内边距。时间线选择会忽略最高 4px 的指针抖动，包括在裁剪手柄上的点击，因此选择片段不会引入起始间隙。项目和预设名称会在各自行内截断。录制器保持其紧凑的桌面布局。

`src/components/ui` 中的适配器将现有 Recordly 的 state/callback props 转换为 HeroUI API。时间线几何、裁剪手柄、视频画布、字幕画布编辑器、波形图和原生文件输入仍保留为应用专属；HeroUI 不会替换这些编辑引擎。录制/导出/项目逻辑被保留，可为空的 ref 类型已针对 React 19 更新。

## 验证

```sh
npm run typecheck
npm test
npx vite build
npx playwright install chromium
npm run test:ui
```

生产构建同时包含渲染进程以及 Electron main/preload 打包产物。它不是安装程序打包运行。

浏览器测试使用一个显式的模拟 Electron 桥接和一个生成的六秒视频素材；它们从不启动真实的屏幕录制。第二个变化帧素材验证时间线缩略图能解码出不同的源帧。它们覆盖控件回调与键盘行为、模态框焦点、导出设置、预设、裁剪、注释格式化/撤销、项目菜单、录制器浮层、倒计时和更新窗口、主题切换、Advanced 状态、颜色编辑、壁纸上传以及键盘/悬停移除，还有在 800–1440px 下、有无 macOS 窗口控件时头部/播放的对齐。截图和失败追踪会输出到被忽略的 `test-results/` 目录。

`npm run dev:ui` 只启动 Vite 用于浏览器检查；组件 fixture 位于 `/tests/ui/controls.html`。真实编辑器需要 Electron 或测试桥接。原生录制、设备权限和端到端媒体导出仍需要在目标平台上进行桌面冒烟测试。
